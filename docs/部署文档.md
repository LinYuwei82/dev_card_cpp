# DevCard 部署文档（Windows）

适用版本：M7 新架构（`win/m7-server`）。本文只写步骤与验证方法，不写代码。
版本真值只有 `VERSION.txt` 一处；程序里显示、安装包文件名都从它来。

> **从源码构建（新 clone）**：`third_party/webview2` 被 `.gitignore` 排除，clone 后不含该目录，configure 前必须先运行
> `powershell -ExecutionPolicy Bypass -File shell/win/fetch-webview2.ps1`。脚本固定取 WebView2 SDK `1.0.2903.40`，
> 先校验 SHA256（`EF128016DD1E51C59178C827ED5B8AA3322C57AFA8675D930F8109505542AD74`）再解压；内网或离线环境用
> `-LocalPackage <Microsoft.Web.WebView2.1.0.2903.40.nupkg 路径>` 指向已下载的同版本包，校验口径不变。

## 1. 安装与首次启动

**两种形态，选一种**

| 形态 | 程序位置 | 数据目录 | 是否支持自动更新 |
|---|---|---|---|
| 安装版 | `%LOCALAPPDATA%\Programs\DevCard`（per-user，**不需要 UAC**） | `%LOCALAPPDATA%\DevCard\data` | 支持（前提是 Release 带了 `setup.exe`，见 §7） |
| 绿色版 | 解压到任意目录 | exe 旁 `data\` | 不支持，手动替换程序目录 |

**步骤**

1. 安装版：运行 `DevCard-<版本>-setup.exe`，按向导完成（无需管理员）。
   绿色版：解压 zip 到目标目录，不要解压到 `Program Files` 或桌面同步目录。
2. 首次启动，二选一：
   - 本地窗口模式：双击 `DevCard.exe`（只监听 `127.0.0.1`，外网访问不到）。
   - 网络版：运行 `devcard-server.exe --server`。只有一块私有 IPv4 时自动选它；
     有多块网卡会报 `bad_listen` 并列出候选，用 `--listen <ip>` 指定。
3. 看启动日志（控制台输出）确认四项：版本与 schema、配置文件来源、数据目录绝对路径、
   形态与来源、监听地址、登录限流阈值。

**验证**

- 日志出现 `数据目录: ...（来源：形态默认（安装版））` 或 `（便携版）`，
  且目录真实存在、可写。
- 首次启动日志出现「首次启动：已生成初始账号，密码写入 …\初始账号密码.txt」。
- 浏览器打开 `http://127.0.0.1:18080/` 能看到登录页。

## 2. 端口与防火墙

**端口**

- 默认 `18080`。三种改法，优先级从高到低：命令行 `--port`、环境变量 `DEVCARD_PORT`、
  配置文件 `devcard-server.json` 的 `port`。
- 端口被占用时启动失败，错误码 `port_in_use`，提示里给出 `netstat` 查占用的命令。

**防火墙（只对网络版）**

1. 放行 TCP 入站 `18080`（或你改后的端口），作用域选「专用网络」，
   不要对「公用网络」放行。
2. 不要让服务直接暴露到公网：网络版只接受回环与 RFC1918 来源（10/172.16–31/192.168），
   其他来源一律 403 `forbidden_source`。这层是兜底，不替代防火墙。
3. 监听 `0.0.0.0` / `::` 需要显式加 `--allow-any`，会打印警告——除非确认处在可信内网，
   否则不要用。

**验证**

- 同网段另一台机器：`curl http://<服务端IP>:18080/api/health` 应返回 200。
- 用机器名或域名访问时若返回 421 `bad_host`，说明 Host 不在白名单（防 DNS rebinding）：
  把该名字加进配置文件的 `allowed_hosts`，或用 IP 访问。
- 从非内网地址访问应被 403 拒绝（可用手机热点验证）。

## 3. 首次登录与改密

1. 打开 `http://<地址>:18080/`，用户名 `root`，密码取自数据目录里的
   `初始账号密码.txt`（首次启动生成，含每个账号一行）。
2. 登录后系统强制改密，改完才能用其他功能。
3. 所有账号都不再处于「必须改密」状态后，`初始账号密码.txt` 会被自动删除。

**验证**

- 未改密时直接调其他接口，返回 `403 must_change_password`（服务端拦，不是页面藏入口）。
- 改密后调 `/api/bootstrap` 返回 200，且响应里的 `must_change_password` 为 `false`。
- 改密完成后确认 `初始账号密码.txt` 已消失；若还在，说明还有账号没改密。

## 4. 数据目录与备份

**目录内容**（都在同一个数据目录下）

- `devicedb.db`：主库（台账、用户、设置）。
- `backups\`：备份文件。
- `assets\`：自定义图标等。
- `updates\`：自动更新下载的包与安装结果 `install-result.json`。
- `instance.lock`：多实例锁文件（含占用者 PID、启动时间、监听地址）。

**备份**

1. 界面里点「备份」，或升级/批量导入前手动备份一次。
2. 生成的文件名形如 `devcard-20261115-073000-manual.db`（时间戳 + 标签），
   落在 `backups\`。同名冲突会追加 `-2`、`-3`。
3. 备份是单个 SQLite 文件，直接复制到别的盘/网盘即可；**不要只备份程序目录**。
4. 恢复：把备份文件放回 `backups\`，在界面选它恢复。恢复前系统会**自动先做一次
   `pre-restore` 备份**，恢复错了还能退回去。

**验证**

- 备份文件名里的时间戳与你操作的时刻一致（本地时区）。
- 备份后用任意 SQLite 工具打开该文件，`SELECT count(*) FROM device` 与界面条数一致。
- 恢复后条数与备份时一致，且 `backups\` 里多出一个 `pre-restore` 文件。

## 5. 升级步骤

**安装版（自动更新）**

1. **发布硬前置：Release 必须带 `DevCard-<版本>-setup.exe`。缺这个附件就等于 Windows
   自动更新不可用**——下载与校验能跑通，但触发安装会被服务端拒
   （`400 install_package_invalid`，只接受 `.exe` 安装包）。绿色版 zip 不能代替。
2. 页面提示有新版本 → 点「立即安装」→ 程序下载并校验整包（SHA256 + 字节数）→
   安装器静默运行（`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS`）→
   按原路径、原参数重启。
3. 结果口径：**安装器退出码 0 且版本号确实变化**才算成功；否则界面显示
   「上次安装未成功：安装器退出码 X｜版本 A → B」，不显示成功。
4. `exit_code 5` 表示安装器关不掉旧进程（常用于另一个实例还占着 exe）：
   安装器回滚、程序目录仍是旧版本。**处理办法**：关掉占用进程（任务管理器里所有
   `DevCard.exe` / `devcard-server.exe`）后重试，不要手工删文件。
5. **升级中断**：如果升级过程中协助器被杀、或机器在安装途中重启，下次启动时
   `GET /api/update/install-result` 会返回 `state=interrupted`（判据是状态文件停在
   `installing` 且超过 300 秒），界面显示「升级被中断」，不会显示成功。
   处理办法：确认程序目录版本（启动日志）正常后重新点一次「立即安装」。

**绿色版（手动）**

1. 下载新 zip，解压到新目录。
2. 把旧目录的 `data\`、`devcard-server.json` 复制过去（**不要复制 exe / dll**）。
3. 停旧、启动新。绿色版不自动替换，与「绿色版不改程序目录」的规则一致。

**验证**

- 启动日志的版本号与 `VERSION.txt` 一致。
- `GET /api/bootstrap` 返回的 `version` 是新版本。
- 升级后数据目录四个文件（`devicedb.db` 等）哈希逐字节不变——升级只换程序，不迁数据。

## 6. 多实例为什么会被拒

同一个数据目录只允许一个服务实例，三层判据：锁文件、库文件身份、库内心跳。
第二个实例会**直接退出，退出码 3**，stderr 为 `启动失败[instance_in_use]: …`，
提示里带占用者的 PID、启动时间与监听地址。

- 这是有意的：两个进程同时写同一个 SQLite 库会互相覆盖，且端口/会话无法共享。
- 需要并行跑多个实例（例如两个部门各一套）时，用**不同的数据目录 + 不同端口**，
  不要指向同一个 `data`。
- 程序上次被强杀留下的锁，会按 PID 与超时自动接管，不需要手工删 `instance.lock`；
  确实要手工清理时，先确认没有进程在用该目录。

## 7. 并发容量（实测口径）

单机实测（同一台机器上压测，来源 `127.0.0.1`，每个请求新建连接，持续 5 秒）：

| 并发线程 | 吞吐 | 结果 |
|---|---|---|
| 5 | 707.5 req/s | 全 200，无连接失败 |
| 16 | 1894.9 req/s | 全 200，无连接失败 |
| 20 | 2679.5 req/s | 全 200，无连接失败 |

- 20 并发这一档此前会出现大量连接失败，现在用构建期定义
  `CPPHTTPLIB_LISTEN_BACKLOG=128` 抬高（**未改内嵌依赖本体**）。这个值是留余量，
  不是算出来的精确阈值：上限落在 16→20 之间，取决于 accept 队列深度；
  改回默认 5，20 档就退回「大量连接被拒」，16 档仍可全 200。
- 局域网 5–20 人同时使用在实测范围内；更大并发未测，不要按线性外推承诺。
- **这组数字的边界（比数字本身重要）**：三档压测的来源全是 `127.0.0.1` 回环，
  **没有真实交换机、没有网络 RTT、没有杀毒软件或防火墙过滤**。它证明的是
  「服务端在 20 并发建连下不丢连接、不出 5xx」，**不证明「局域网 20 个人同时用没问题」**。
  真实局域网的带宽、丢包、安全软件扫描与交换机排队都未纳入，别把上面的吞吐读成后一种结论。
- 完整排查过程（原始现象、怎么排除客户端复用、`httplib` 锚点、单变量改动、
  阈值含义、为何不再测 64）见技术方案 §10.7「20 线程未达标 → 达标：一次单变量排查的完整记录」。
  其中「backlog=5 时 16 档也在付代价」（4703→9503 请求、873→1895 req/s）对调参有参考价值。

**验证**

- 同一目录起第二个实例：`echo %ERRORLEVEL%` 为 3，stderr 出现 `instance_in_use`。
- 关掉第一个后再次启动：正常起来，端口一致。

## 8. 启动失败码表

程序以退出码 + stderr 的 `启动失败[<code>]: <说明>` 报告失败，判据靠退出码与错误码，
不要靠中文断句。

| 退出码 | 错误码 | 含义与处理 |
|---|---|---|
| 3 | `instance_in_use` | 同一数据目录已有实例在跑。见 §6 |
| 2 | `bad_config` | 配置文件有错（未知键、类型不对、`--config` 指向的文件不存在）。按提示改 `devcard-server.json` |
| 2 | `bad_listen` | 监听地址选不出来（多块私有网卡 / 没有私有网卡）。用 `--listen <ip>` 指定 |
| 1 | `data_dir_unwritable` / `data_dir` | 数据目录不可写，且**不会**回退到临时目录（避免出现空台账）。提示里列出四条候选来源，按其一显式指定 |
| 1 | `port_in_use` | 端口被占用。换端口或结束占用进程（见 §2） |
| 1 | `font_missing` / `font_corrupt` | 随包字体缺失或损坏。重新解压/重装，不要手工改 `fonts\` |
| 1 | `web_assets` | 内嵌前端与源文件不一致（构建产物被改动）。重装或重新构建 |
| 1 | 其他 `AppError` | 见 stderr 里的码与说明 |
| 1 | 无码（`启动失败: …`） | 非 `AppError` 的异常（如文件系统异常）。这类没有稳定分类，按说明处理 |

**验证**

- 故意让配置文件多一个键：退出码 2、stderr 为 `启动失败[bad_config]`。
- 同时起两个实例：第二个退出码 3、stderr 为 `启动失败[instance_in_use]`。
- 把数据目录设为只读：退出码 1、stderr 为 `启动失败[data_dir_unwritable]`。

## 9. 登录限流（运维要知道的三件事）

1. **只管两条接口**：登录 `/api/session/login` 与改密 `/api/users/password`。
   没有全局限流——局域网里先被打死的是静态页与轮询，全局限流会连带拖垮正常界面。
2. **规则**：同一来源 IP 或同一用户名，5 分钟内连续失败 5 次 → 锁 60 秒；
   期间返回 `429 too_many_requests` 并带 `Retry-After`（秒）；
   锁定期内**即使密码正确也 429**；登录成功清零。
   `127.0.0.1` / `::1` 整体不计（本机界面不会被自己锁住）。
3. **限流是内存实现、进程重启清零**：不落库，也不跨机器共享。
   多台服务端各自计数；重启后计数归零属预期行为，不要当成「限流失效」。

**配置**（`devcard-server.json`，默认开启）

| 键 | 默认 | 说明 |
|---|---|---|
| `rate_limit_enabled` | `true` | 总开关 |
| `rate_limit_max_failures` | `5` | 同键连续失败次数阈值 |
| `rate_limit_window_seconds` | `300` | 计数窗口 |
| `rate_limit_lock_seconds` | `60` | 锁定时长 |

**验证**

- 连续输错 5 次后第 6 次：HTTP 429，响应头有 `Retry-After`，响应体含 `too_many_requests`。
- 锁定期内输入正确密码：仍 429。
- 等 60 秒后再用正确密码：可以登录。
- 在服务器本机（`127.0.0.1`）重复上述操作：不会出现 429。
- 把 `rate_limit_enabled` 改成 `false` 重启：连续失败不再出现 429。

## 10. 发布前 checklist

- [ ] `VERSION.txt` 已改，且全仓只有这一处版本真值。
- [ ] 构建号不手填：`publish_macos.sh` / `publish_windows.ps1` 默认调 `tools/release/gen_build.py` 取号
      （`YYYY * 10^12 + git rev-list --count`，16 位），macOS 与 Windows 必须同号；
      需覆盖时显式传 `-Build` / `DEVCARD_BUILD`。`guard.py preflight` 会校验清单 `build`
      等于编译注入值，并阻断「同版本两平台 build 不一致」（单平台热修加 `--allow-build-drift`）。
- [ ] Release 附件含 `DevCard-<版本>-setup.exe`（**Windows 自动更新的硬前置**）。
- [ ] 安装版实跑：静默安装 → 启动 → 登录 → 改密 → 台账可见 → 卸载后数据目录保留。
- [ ] 升级实跑：旧版 → 新版，`exit_code 0` 且版本号变化；数据目录哈希不变。
- [ ] 绿色版 zip 解压即用，`data\` 在 exe 旁；明确它不支持自动安装。
- [ ] macOS 的 DMG 由 `tools/package/package_macos.sh` 一条命令出（签名 + 公证 + staple）。Sparkle 自更新已落地：发布时用 `tools/release/publish_macos.sh` 一次完成出包、签名、appcast 与 v2 `manifest.json` 生成与上传。详见技术方案 §10.4.2 阶段三。
- [ ] macOS 产物记录**身份哈希（App 内容层）**：`DevCard.app/Contents/MacOS/DevCard` 与
      `Contents/Info.plist` 的 SHA256（`package_macos.sh` 每次打印）。**DMG 的 SHA256 只作传输校验，
      不作身份**；DMG 精确字节数不作体积基线（容器 GUID 噪声约 10 B，见技术方案 §10.7）。
- [ ] 若用 `--skip-build` 出包，必须同时记录 bundle 内可执行文件 SHA256 与被复用的
      `build/release` 对应 commit；缺任一项，该产物的体积与哈希不得写进基线。
- [ ] **macOS 签名与公证**：`package_macos.sh` 已按 Developer ID 逐层签名 + `notarytool` 公证 +
      `stapler staple`，`spctl --assess` 应为 `Notarized Developer ID`；发布前核对脚本输出的
      签名与公证结果，失败不得发版。2026-11-17 之前的 ad-hoc 旧包仍需用户手动放行，不再分发。
- [ ] **guard.py preflight 跑通**：发布脚本里会自动调 `python3 tools/release/guard.py preflight`，
      强制 DevCard v2 清单同时含 `platforms.macos + platforms.windows`，缺失任一平台段直接 `die`；
      还会提醒 Windows 构建号必须等于 CMake 注入的 `DEVCARD_BUILD` 值（发布脚本取号 → CMake configure → 二进制 → manifest.json build 字段，四处同值）。**发布后**再跑一次
      `python3 tools/release/guard.py verify-live` 核对线上清单与 Content-Type / Cache-Control /
      Sparkle edSignature。
- [ ] **Windows 构建号注入链路验证**（12600k 上）：`powershell -File tools\release\verify_build_stamp.ps1`
      必须 T1–T7 全 PASS（configure 注入日志 → CMakeCache → devcard_core_tests 断言 → EXE 内 grep 标记 →
      fallback 回退 → manifest_v2.py 生成）。没注入构建号时二进制内找不到 `DEVCARD_BUILD=` 标记，
      同版本重发无法触发更新，等于白改版本号。
- [ ] 启动失败码表核对过一遍（§8），新增错误码时两处映射一起补。
